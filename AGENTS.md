# AGENTS.md

This repository is a toolkit that lets AI coding agents build, test, export and plan Godot 4.7 games (GDScript or C#),
for any genre. One PowerShell 7 script runs locally on Windows and, packed into a workflow, on GitHub Linux runners.

## Layout

- `ci/godot/godot-ci.ps1` entry point: `test build export setup detect doctor init plan bench shot status audio soak credits sfx`, all with `-Json`.
- `ci/godot/lib/*.ps1` one concern per file: Common, Setup, Detect, Report, Runners, Doctor, Init, Plan, Measure, Status, Architecture, Juice, Audio, Assets, Localization, Soak, Data, TextSize, Layout, Credits, Store, Web, Platforms, Sfx.
- `ci/godot/tools/` `validate.gd`, `flows.gd`, `bench.gd`, `shot.gd`, `textsize.gd`, `layout.gd`, `notices.gd` (run inside Godot), `web-smoke.mjs` (Node.js and Playwright, for `export -Run` of Web presets), `Sfxr.cs` (bfxr2's sound synth in C#, compiled by `sfx` with `Add-Type`; Apache-2.0 and MIT), `Test-Skills.ps1` (skill validator),
  `Update-Versions.ps1` and `Invoke-Canary.ps1` (the weekly check against new releases), release/PR-comment tools.
- `tests/` self-tests with deliberately broken fixtures: the skill validator's, the architecture rules', the juice runner's (`juice-fixture`), `doctor`'s (`doctor-fixture`), `audio`'s (`audio-fixture`, sounds generated by `Test-Audio.ps1`) and the asset manifest's (`assets-fixture`), the `l10n` runner's and `shot -Locale`'s (`l10n-fixture`), `shot -ColorVision`'s (`colorvision-fixture`; `Test-ColorVision.ps1` needs Godot and a display), `soak`'s (`soak-fixture`, a small ENet game, and `soak-fixture-cs`, a C# server that catches SIGTERM; `Test-Soak.ps1` needs Godot), the `data` runner's (`data-fixture`), the `textsize` runner's (`textsize-fixture`, needs Godot), the Steam checks' (`steam-fixture`), the `layout` runner's (`layout-fixture`, needs Godot), Web `export -Run`'s (`web-fixture`; `Test-Web.ps1` needs Godot's templates, Node.js and a Playwright browser), `doctor`'s Web and Android checks (`Test-Platforms.ps1`), `credits`' (`credits-fixture`; `Test-Credits.ps1` needs Godot), the skill's capture mode (`capture-fixture`, C#; `Test-Capture.ps1` needs Godot and a display), `doctor`'s Steam store art check (`Test-Store.ps1`, images it generates), `bench`'s hotspots (`bench-fixture`; `Test-BenchHotspots.ps1` needs Godot and a display), the placement checker's (`placement-fixture`; `Test-Placement.ps1` needs Godot), the plan template's gates (`Test-Plan.ps1`), the process time limit's (`Test-ProcessTimeout.ps1`), the download failure code (`Test-DownloadFailed.ps1`, with or without a network, about 15 s), the `dotnet` runner's guard against gdUnit4 tests found but not run (`Test-TestsNotRun.ps1`, synthetic TRX), `test`'s failure delta against the previous run (`Test-FailureDelta.ps1`, synthetic history), `test -Retry`'s flaky tests and `quarantine.json` (`flaky-fixture`, GUT; `Test-Flaky.ps1` needs Godot, `-NoGodot` runs its synthetic part), error keys and `status`'s `recurringErrors` (`errorkeys-fixture`; `Test-ErrorKeys.ps1` needs Godot and git, `-NoGodot` runs its synthetic part), shaders quoted in skills (`Test-SkillShaders.ps1`, needs Godot), links and quoted paths in the docs and skills
  (`Test-DocLinks.ps1`), `doctor`'s repository checks (`Test-RepoHygiene.ps1`, a broken project made in a temporary
  folder, since a reserved name or case twins committed here would break Windows checkouts), `sfx`'s sounds against
  values recorded from bfxr2 (`Test-Sfx.ps1`), and the mono option measured in the engine (`mono-fixture`; `Test-MonoAudio.ps1` needs Godot).
- `ci/godot/templates/` files `init`, `plan`, `/game` and the architect copy into a game (`plan.json`, `AGENTS.md`, `GDD.md`, `ADR.md`, `STYLE.md`, `TECH-DEBT.md`, `TRAILER.md`), `licences/` (SPDX texts `credits` ships for MIT, ISC, BSD, Apache-2.0, OFL-1.1 and Zlib), and `genres-uw.json` (University of Washington, CC BY-NC-SA 4.0 with permission) and `genres.json` (Wikidata, CC0), the genre vocabularies.
- `.agents/skills/*/SKILL.md` the skills shipped to games (`init -Agents` copies them; the plugin loads them in place).
- `.claude-plugin/`, `agents/`, `hooks/` the Claude Code plugin: manifest and marketplace, the `godot-verifier` and `godot-architect` subagents, the Stop hook.
- `evals/` `claude plugin eval` cases (with and without the plugin); `docs/research.md` the measurements behind them.
- `benchmark/` the token benchmark (`Invoke-TokenBenchmark.ps1`, `token-benchmark.json`); each real run costs money, `-DryRun` does not.
- `.github/actions/godot`, `.github/workflows/godot.yml` composite action and reusable workflow.
- `examples/breakout` (C#, every framework) and `examples/gdscript` (GUT): the integration fixtures.
- `docs/` per-topic documentation; `docs/json.md` is the output contract.

## Working here

- PowerShell 7.2+, strict mode 3.0, `$ErrorActionPreference = 'Stop'`. Wrap results that may be empty or single in `@(...)`
  and iterate with `foreach`; never index a pipeline result (PowerShell unrolls one-item arrays).
- Short helper names collide with built-in aliases (`r` is Invoke-History, `rp` is Remove-ItemProperty, `h` is Get-History): use
  Verb-Noun names. In array literals `,` binds tighter than `+`: `@(1, 2 + 3)` is `(1, 2) + 3`, three items `1, 2, 3`; write `@(1, (2 + 3))` for `1, 5`. Overwrite a zip with
  `Compress-Archive -Force` instead of deleting wildcard paths. Windows machines have no Python: keep tooling in PowerShell or GDScript.
- Never `Write-Output` from helpers; return values are the pipeline. Logs use `Write-Host`/`Write-CiLog` (stderr in `-Json`).
- Fail with `Stop-GodotCi "message" 'stable-code'`. Codes are API: add to `docs/json.md`, never rename.
- `$script:JsonDoc` is the `-Json` result; add fields with `Set-JsonField`. The `-Json` switch and state must not share a name
  (PowerShell variables are case-insensitive).
- Scripts run inside Godot (`-s tools/x.gd`) cannot see the scene's `_ready` until the first frame: `await process_frame` after
  `add_child` before reading anything the scene sets up.
- `bench`, `shot` and `audio -Mix` need a display (and `audio` needs ffmpeg). Here, start `Xvfb :99 &` and set `DISPLAY=:99`; do not use `xvfb-run`, which merges stderr into
  stdout and breaks `-Json`.
- The `.gdignore` files at the repository root and in `ci/godot/` keep the kit out of a game it is placed inside (Godot neither
  imports nor exports it, and `Find-ProjectFiles` skips folders that have one). Do not remove them.
- Verify with the examples: `pwsh ci/godot/godot-ci.ps1 test -Project examples/breakout/game` and `-Project examples/gdscript`
  must be green; `doctor` and `plan` on both. Changing a version matrix entry means re-running both on that Godot.
- Skills: `pwsh ci/godot/tools/Test-Skills.ps1` and `pwsh tests/Test-SkillFixtures.ps1` must pass; architecture rules: `pwsh tests/Test-ArchitectureFixtures.ps1`; juice log: `pwsh tests/Test-JuiceLog.ps1`; process time limit: `pwsh tests/Test-ProcessTimeout.ps1`; download failure: `pwsh tests/Test-DownloadFailed.ps1`; failure delta: `pwsh tests/Test-FailureDelta.ps1`; flaky and quarantine: `pwsh tests/Test-Flaky.ps1`; error keys: `pwsh tests/Test-ErrorKeys.ps1`; tests not run: `pwsh tests/Test-TestsNotRun.ps1`; audio: `pwsh tests/Test-Audio.ps1` (`-Mix` with a display); assets: `pwsh tests/Test-AssetManifest.ps1`; localization: `pwsh tests/Test-Localization.ps1`; soak: `pwsh tests/Test-Soak.ps1`; data: `pwsh tests/Test-Data.ps1`; plan gates: `pwsh tests/Test-Plan.ps1`; credits: `pwsh tests/Test-Credits.ps1`; store art: `pwsh tests/Test-Store.ps1`; text size: `pwsh tests/Test-TextSize.ps1`; bench hotspots: `pwsh tests/Test-BenchHotspots.ps1` (with a display); Steam: `pwsh tests/Test-Steam.ps1`; layout: `pwsh tests/Test-Layout.ps1`; web: `pwsh tests/Test-Web.ps1`; platforms: `pwsh tests/Test-Platforms.ps1`; token benchmark: `pwsh tests/Test-TokenBenchmark.ps1`; skill shaders: `pwsh tests/Test-SkillShaders.ps1`; doc links: `pwsh tests/Test-DocLinks.ps1`; repository checks: `pwsh tests/Test-RepoHygiene.ps1`; sound effects: `pwsh tests/Test-Sfx.ps1`; mono: `pwsh tests/Test-MonoAudio.ps1`. A skill description says only when to use it, never how.
  Commands, flags, error codes and versions quoted in a skill are checked against the real script, `docs/json.md` and `examples/breakout`.
- Commit as the repository owner. Do not add AI attribution trailers to commits or PR descriptions.
- Do not rewrite pushed history.
- Blocked access (a site, tool, credential or permission out of reach) is never a reason to drop a good idea: ask the
  owner for help, do what does not depend on it, and write down what could not be done and why in `docs/roadmap.md`.
