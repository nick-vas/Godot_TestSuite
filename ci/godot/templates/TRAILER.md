## Genre, hook, content

The order of the trailer. A viewer cannot care how much there is until they know what the game is.

| Beat | Question | Answer |
|---|---|---|
| Genre (first 5 seconds) | Which genre is this, and which opening shot says so without words? | |
| Hook (most of the trailer) | How is it different within that genre, and why is that interesting, not only different? | |
| Challenge | How does it challenge the player? | |
| Depth | Why would someone play it for a long time? | |
| Content (last, if there is time) | Bosses, levels, modes, unlocks | |

## Mechanics a viewer can read

A viewer sees the screen, not the controller. For every core mechanic, write what shows that the player caused it. An
empty or "nothing" cell is design work now (feedback, animation, sound: `godot-juice`), not a trailer problem later.

| Mechanic | What the player does | On-screen feedback a viewer sees | Change needed to make it visible |
|---|---|---|---|
| | | | |

Choices count as mechanics: show what the player is weighing (a highlight moving between options reads; a menu answered
with a button press does not).

## Check

- Shown or read to someone who has not seen the game: could they name the genre and the mood? What did you notice while
  they watched?
- Could it be pitched without comparing it to other games, and without someone playing it for hours?
- Among a hundred games, would its screenshots or this trailer be picked out?
- Does it excite you? If no trailer you can imagine for it would, say so in the prototype verdict (docs/DECISIONS.md).
